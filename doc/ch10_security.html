10.2. Безопасность

  • Устройство: ключ в eFuse, сегменты AES-GCM — украденный бейдж/карта не читаются; mTLS-идентичность на устройство, отзыв сертификата при пропаже; подписанные OTA.
  • Транспорт: WPA3 на своей AP, WireGuard шлюз→облако; бейджи не видят интернет вообще (VLAN только до шлюза).
  • Облако: шифрование S3 at-rest, доступ к аудио — только через сервис выдачи с RBAC и журналированием каждого прослушивания (кто, что, когда — журнал виден СБ); прод-доступ инженеров — по break-glass процедуре.
  • Минимизация: PII-маскирование транскриптов вторым проходом (имена, телефоны, паспорта); обучающие подборки — только маскированные; фрагменты со спецкатегориями (здоровье, семья — клиент случайно рассказал) детектируются LLM и вырезаются из хранения (юридическое требование, см. ниже).

10.3. Правовая конструкция (РФ, август 2026)

Проверено по первоисточникам и разъяснениям (список — прил. Б); финальный пакет документов подлежит валидации практикующим юристом по ПДн.

  • Запись — персональные данные, но не биометрия, пока голос не используется для установления личности (ст. 11 152-ФЗ: оба условия должны выполняться). Поэтому в системе — архитектурный запрет voice-ID: роли определяются геометрией микрофонов (гл. 4), голосовые профили не строятся и не хранятся. Нарушение этой границы переводит систему в режим биометрии: письменные согласия, УЗ-1/УЗ-2, штраф за утечку 15–20 млн ₽.
  • Основание обработки клиентов — связка: заметные таблички «ведётся аудио- и видеозапись» + устное уведомление в начале предметного разговора (пункт скрипта менеджера, контролируется самим же разбором) + явное согласие отдельным документом на этапе анкеты/записи на тест-драйв (с 01.09.2025 согласие — только обособленная форма) + п. 5 ч. 1 ст. 6 152-ФЗ (преддоговорные отношения) для реальных покупателей. «Зашёл поглазеть» без последующего контакта — разговор не персонализируется: остаётся анонимной статистикой без связки с CRM, аудио удаляется по короткому TTL (30 дней).
  • Сотрудники: ЛНА «о контроле качества обслуживания» (цели: контроль качества, обучение, разбор споров; доступы; сроки), ознакомление под подпись, доп. соглашения; использование записей только в заявленных целях — дисциплинарка на записях при цели «обучение» юридически уязвима, это же условие приживаемости (гл. 11). Арбитражная практика запись переговоров сотрудников с клиентами при ЛНА поддерживает.
  • Локализация (ч. 5 ст. 18): весь конвейер в РФ; зарубежные ASR/LLM API исключены архитектурно (штраф 1–6 млн ₽, повторно 6–18 млн). Облако — сегмент «152-ФЗ» (УЗ-3 целевой уровень по ПП 1119), договор поручения обработки с провайдером.
  • Оператор: уведомление РКН (обновить: цели, аудио, облако), политика, ответственный, модель угроз, меры приказа ФСТЭК №21, регламент утечек 24 ч/72 ч. Лицензии ФСТЭК не требуется (обрабатываем собственные ПДн).
  • Ретенция: аудио 6 мес (авто-TTL в S3), маскированные транскрипты 24 мес, разборы/агрегаты — без ПДн, бессрочно. Права субъектов: выдача/удаление по запросу — реализуется штатным API (данные и так связаны с клиентом в CRM).
  • Главный риск — утечка массива записей: >1 000 субъектов → 3–5 млн ₽, повторно — оборотный штраф 1–3% выручки (от 20 млн). Дизайн минимизации: компактный периметр аудио (один сервис выдачи), маскирование, вырезание спецкатегорий, короткая ретенция, журналирование доступа. Тайна связи (126-ФЗ) к живым разговорам не применяется — подтверждено; при добавлении записи телефонии потребуется отдельный контур.
