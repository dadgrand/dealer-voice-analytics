# Система аналитики живых разговоров в дилерском центре

Материалы к тестовому заданию (архитектурный трек): проектирование системы, которая
записывает разговоры менеджеров с клиентами в шоуруме, превращает их в структурированный
разбор и доводит до CRM и руководителя отдела продаж; второй этап — подсказки менеджеру
в реальном времени.

**Основной артефакт — PDF-документ** (34 стр., 6 диаграмм): архитектура, хардвер до уровня
партномеров, расчёты, юридика, план внедрения. Этот репозиторий — воспроизводимая часть:
расчётная модель, PoC пайплайна и исходники, из которых собирается документ.

## Ключевые цифры (консервативный сценарий, цены августа 2026)

| Метрика | 100 менеджеров | 1000 менеджеров | Бюджет |
|---|---:|---:|---|
| CAPEX на менеджера (бейдж $52 + ЗИП + док + доля шлюза) | **$98** | **$75** | ≤ $100 |
| OPEX на менеджера в месяц | **$11.7** | **$8.9** | ≤ $15 |
| Задержка подсказки (этап 2), от слов клиента до часов | ≈ 1.8 с | ≈ 1.8 с | ≤ 3 с |

Решение в пяти строках: носимый бейдж собственной разработки (ESP32-S3, два MEMS-микрофона,
Opus на борту) → своя сеть на площадке (мини-ПК-шлюз + своя Wi-Fi AP + LTE, ноль зависимости
от Wi-Fi дилера) → батч-обработка в российском облаке (152-ФЗ): GigaAM-v3 (ASR) + pyannote
(диаризация поверх канальной асимметрии бейджа) + T-Pro 2.0 (LLM-разбор) → свой модуль в
самописной CRM с трёхступенчатой связкой «разговор ↔ сделка».

## Состав репозитория

```
calc/model.py     — расчётная модель юнит-экономики: все цифры документа воспроизводятся
                    одним запуском (нагрузка, GPU-парк, хранение, OPEX/CAPEX, два сценария)
poc/pipeline.py   — PoC пайплайна этапа 1 на CPU: WAV → VAD → разделение ролей по
                    асимметрии каналов → ASR (GigaAM-v3) → JSON-разбор
diagrams/         — исходники диаграмм документа (SVG)
doc/              — исходники PDF: главы (HTML), стиль, сборщик (paged.js + Chrome DevTools
                    Protocol — оглавление с номерами страниц и колонтитулы)
research/         — конспекты веб-исследования цен и бенчмарков с источниками и датами
```

## Расчётная модель

```bash
python calc/model.py
```

Печатает полный расчёт для 100 и 1000 менеджеров в консервативном и оптимистичном
сценариях: поток аудио в пиковый час, GPU-часы по стадиям (ASR/диаризация/LLM), оптимизацию
закупки GPU (выделенные серверы vs почасовая аренда), хранение и итог на менеджера против
бюджетов $100/$15. Все входные допущения собраны в одном словаре с пометками источников —
любое можно поменять и увидеть эффект.

## PoC пайплайна (poc/)

Демонстрирует главную инженерную идею документа — **разделение «менеджер/клиент» по
асимметрии каналов носимого бейджа, без голосовой идентификации** (и потому вне режима
биометрии по ст. 11 152-ФЗ):

```bash
pip install -r poc/requirements.txt
python poc/make_demo_audio.py          # синтез демо-диалога (Windows SAPI) в 2 канала
python poc/pipeline.py poc/demo.wav    # VAD -> роли -> ASR -> analysis.json
```

Выход — JSON по схеме из приложения В документа: реплики с ролями и таймкодами,
извлечённые возражения и чек-лист. Блок LLM-разбора работает через GigaChat API при
наличии `GIGACHAT_API_KEY` (иначе выполняется правило-based заглушка — структура выхода
та же). Подробности — poc/README.md.

## Как собирается PDF

```bash
python doc/build.py       # главы + инлайн SVG + оглавление -> out/document.html
python doc/print_pdf.py   # headless Chrome через CDP, ожидание paged.js -> out/document.pdf
```

Пагинация — paged.js (номера страниц в оглавлении, колонтитулы); печать — через DevTools
Protocol с ожиданием события завершения вёрстки, поэтому результат детерминирован.
