# PoC пайплайна этапа 1

Миниатюра облачного пайплайна из документа, целиком на CPU:

```
demo.wav (2 канала «бейджа») → Silero VAD → разделение ролей по асимметрии
каналов → ASR GigaAM (SberDevices, MIT) → analysis.json по схеме приложения В
```

Что именно демонстрируется:

1. **Разделение «менеджер/клиент» без голосовых профилей.** Канал 0 записан «ко рту
   носителя», канал 1 — «на собеседника»; решение о роли принимается по разнице энергий
   каналов на 20-мс кадрах с медианным сглаживанием. Это ключевая идея архитектуры: роли
   даёт геометрия микрофонов, система не идентифицирует людей по голосу и потому остаётся
   вне режима биометрии (ст. 11 152-ФЗ). В проде поверх этого приора работает pyannote —
   для дочистки «дальней» речи (второй клиент, соседние разговоры).
2. **Русский ASR открытой моделью.** PoC использует GigaAM **v2** CTC — актуальный
   pip-релиз (`pip install gigaam`); в проде — v3 (WER на телефонии на ~10% ниже).
   Первый запуск скачивает веса (~0.9 ГБ) в `~/.cache/gigaam`.
3. **Структурированный разбор.** По умолчанию — правило-based заглушка (возражения,
   чек-лист менеджера, сущности для матчинга с CRM) в той же JSON-схеме, что и прод;
   с `--llm gigachat` и `GIGACHAT_API_KEY` в окружении — реальный вызов GigaChat.

## Запуск

```bash
pip install -r requirements.txt
python pipeline.py demo.wav              # готовое демо-аудио из репозитория
python pipeline.py demo.wav --model v2_rnnt   # вариант точнее/медленнее
```

`demo.wav` — синтетический диалог (Windows SAPI), сведённый в два канала с реалистичной
асимметрией (менеджер: +6 дБ в «своём» канале; клиент: −6 дБ). Пересоздать:
`python make_demo_audio.py` (только Windows; на других ОС используйте готовый файл или
любой собственный двухканальный WAV 16 кГц).

## Ожидаемый выход

Консоль: список реплик с ролями и таймкодами; `analysis.json`: транскрипт + возражения
(«дорого», упоминание конкурента, «подумаю») со статусом отработки + чек-лист менеджера
(уведомление о записи, трейд-ин, тест-драйв, контакт, следующий шаг) + сущности для
сопоставления со сделкой в CRM.

## Ограничения PoC (сознательные)

- Синтетический звук вместо шоурума: PoC показывает механику, не WER в бою — оценка
  качества на реальном шуме описана в документе (гл. 4.6) и делается на пилоте.
- Нет pyannote-дочистки и сегментации смены на разговоры — только канальный приор.
- Правило-based «LLM» — заглушка для офлайн-запуска; структура выхода совпадает с прод.
